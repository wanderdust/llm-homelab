# Changes — 2026-11-09

## Why (context for later)

### In the repo (apps/llm/config/model.env)
- **LLAMA_ARG_N_PARALLEL 2 → 1.** Single user. Logs showed every request on slot 0 (slot 1 never used),
  and one Pi session reached ~12k of the 16k per-slot context within minutes. One slot = the whole context.
  Trade-off: requests now queue instead of running in parallel.
- **LLAMA_ARG_CTX_SIZE 32768 → 65536, FLASH_ATTN=on, CACHE_TYPE_K/V=q8_0.** Storing the KV cache at 8-bit
  instead of 16-bit roughly halves memory per token, so ~2x context fits in the same 6 GB.
  Verify: startup log shows type_k/type_v = q8_0 and n_ctx = 65536; nvidia-smi stays < ~5.5 GB.

### Outside the repo
- **Pi (~/.pi/agent/models.json on laptop): contextWindow matched to the server slot, maxTokens 4096 → 8192.**
  contextWindow must equal the server's per-slot context or Pi compacts too late and the server overflows.
  maxTokens raised because Qwen3.5's thinking was using up the output budget ("Response was truncated").
- **Thinking turned down in Pi (/thinking).** At ~27k context, long reasoning made each turn take minutes:
  "Request timed out" and "Auto-compaction failed: Summarization failed" (compaction uses the same small model).
- **Server netplan: `optional: true` on enp5s0.** Boot hung ~2 min on systemd-networkd-wait-online
  waiting for the unplugged Ethernet port. Lesson: `netplan try` over Wi-Fi SSH drops the session and
  auto-rolls back; use `netplan apply` from the console or inside tmux on the server.
- **Cleaned up Failed pods in the llm namespace.** After reboots the GPU pod can be admitted before the
  device plugin is ready (UnexpectedAdmissionError); the failed pods are left behind.

### Still open
- Server still on Wi-Fi: causes "Connection error" mid-session, slow pulls, slow boot. Move to Ethernet.
- HPA scales on CPU, which can't add capacity on one GPU. Decide whether to keep it.
